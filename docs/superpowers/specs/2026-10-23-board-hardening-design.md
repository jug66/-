# 留言板治理和可靠性改造

本设计承接聊天中已确认的七项执行顺序。沿用 Vue/TypeScript、Java 21、Spring/MyBatis 和 PostgreSQL，不引入 Redis、对象存储或 WebSocket 服务。

1. 治理：管理员由服务端 `ADMIN_USER_IDS` 指定已有用户 UUID，不开放自助提权。支持举报、隐藏/恢复单条内容、封禁/解封、锁定根讨论和审计。隐藏保留父子结构，所有公共读路径和图片接口必须遮蔽内容。封禁检查当前数据库状态，使已有会话失效。
2. 上传：用户日配额 100 MiB、来源日配额 500 MiB、待发布容量 50 MiB、全站未清理文件预算 2 GiB、磁盘预留 1 GiB，均可配置。配额按原始字节记账、不因删除退款；按来源、用户、批次串行校验。事务回滚删除新写文件；定时扫描处理无元数据孤儿，失败保留重试。
3. 生产：`prod` profile 启动校验固定游标密钥、HTTPS 公共地址、安全 Cookie、绝对上传目录。开发启动默认保持可用。
4. 缓存：有界 LRU，保护当前可见路径和正在加载的分支，空间不足先聚焦，异步结果必须仍属于当前代次和缓存对象。
5. 导航：祖先按最多 20 条分段向上加载，显式提示还有上级；回复计数指直接回复（含删除/隐藏占位），最近回复时间指直接回复最新创建时间。最近回复和搜索仍用有界分页。
6. 线程状态：open/resolved/locked/archived，resolved 可继续讨论，locked/archived 只读，统一校验根状态，修改状态和发布回复有共享/排他锁协议。
7. 内容后续：作者 15 分钟内编辑正文、显示编辑时间与版本冲突提示；保留受限修订记录，删除时清空修订正文。提供站内回复通知、通知已读和纯文本搜索；用手动刷新/有界定时检查提示新消息，禁止轮询全树、自动插入改变阅读位置。

验证：先以 HTTP 集成测试证明权限、隐藏/恢复、旧会话封禁、配额、幂等、锁帖、祖先分段、计数、编辑/删除修订、通知和搜索失败，再实现；前端验证 LRU、异步草稿隔离和真实浏览器布局。构建后分别报告已验证与未验证的部署边界。
