数据库/API 测试实际覆盖：

1. 注册字段、大小写归一、并发同名注册唯一、密码确认、中文/emoji 字符数和 Argon2id 存储。
2. 登录会话 ID 轮换、读取身份、两个会话独立注销、绝对过期、未知账号与错误密码返回一致文案。
3. 匿名只读、真实 CSRF token 校验、缺失 token 拒绝、作者等未知 JSON 字段拒绝。
4. 全空白内容、2000 个 emoji 边界、超过 32 KiB 的请求拒绝。
5. 真正父子关系、根 ID 继承、越权删除、删除幂等、删除后有效子节点继续回复。
6. 幂等重放、改变内容的同键冲突、父/自身删除后的当前状态返回、事务回滚。
7. 8 个线程同时提交同一请求只创建一条记录。
8. 父删除先提交时拒绝回复；回复先提交时保留回复。
9. 时间完全相同的根和子回复分页无重复无遗漏、根双向排序、错误游标及跨父节点使用拒绝。
10. SQL 注入字符串作为正文保存；非法排序不进入 SQL；响应不返回密码散列。
11. 数据库行锁超时后返回 503 和请求编号，无部分写入。
12. 图片上传校验、待绑定附件归属、留言绑定、公开读取及删除后的文件不可见。
13. 深层上下文返回目标留言、祖先路径和首屏回复，且不改变原有分页关系。
14. 根分页 **2 条业务查询**、子分页 **3 条业务查询**（额外查询附件元数据），通过 MyBatis 查询计数器断言，没有按留言逐条查作者的 N+1。
15. 真实 PostgreSQL 的大数据与执行计划验证。
16. 管理员举报、隐藏/恢复、锁定线程、封禁用户和治理审计；普通用户权限和已有会话封禁路径均验证。
17. 用户图片日额度、临时待发布容量和第二批上传超限响应。
18. 生产密钥校验、深层分支 LRU 使用时间字段和回复计数/最近回复时间响应。

前端状态测试构造 10,001 个连续节点，迭代遍历不依赖递归调用栈；正常视图最多输出 200 条留言。另验证折叠、删除占位、异常循环防护和按 ID 去重。

## 数据规模与查询计划

普通集成测试构造约 **160,083 条留言**，包含 100,000 条规模根留言、一个父节点下 50,000 条直接回复、深度 10,000 的回复链，并成功在叶节点再发布至第 **10,001 层**。

根列表使用 `comment_roots_time`，直接回复与子节点探测使用 `comment_children_time`。执行计划对留言表的全表顺序扫描做回归断言；列表每次最多取 `limit + 1` 条判断下一页。

原始计划、数据库版本、行数和单线程样本在 [规模证据](evidence/scale-evidence.txt)。单线程结果只描述该测试，不用于替代 HTTP 并发压测。

开发过程中修复了两个由真实执行计划暴露的问题：

- PostgreSQL 17 可能把普通相关 EXISTS 改成扫描全表的哈希子计划。
- 单个父节点聚集大量子回复时，无排序的 LIMIT 1 也可能选择顺序扫描。

最终使用与复合索引顺序一致的 `ORDER BY created_at,id LIMIT 1` 子节点探测，并保留偏斜数据分布下的计划检查。没有通过关闭全局顺序扫描或移除性能断言来掩盖问题。

## HTTP 并发实测

环境：AMD Ryzen 9 8945HX，32 个逻辑处理器，约 31.8 GiB 内存；应用、压测客户端和数据库在同一台 Windows 电脑，通过 loopback HTTP 通信。Hikari 最大连接数 12。PostgreSQL **fsync=on、synchronous_commit=on**。

初始数据 100,000 条根留言和 50,000 条同父回复。50 个读取客户端、10 个写入客户端，每个客户端每 200ms 最多发起一个请求；预热 300 秒，测量 60 秒。压测实例的读/写限流调到每 IP 每分钟 1,000,000；正常应用仍采用默认限流。

| 指标 | 实测 |
|---|---:|
| 成功读取 | 14,802 |
| 成功写入 | 2,962 |
| 预热 / 测量失败 | 0 / 0 |
| 读取 P95 | 4.0845 ms |
| 写入 P95 | 4.3810 ms |
| 读取吞吐 | 246.70 次/秒 |
| 写入吞吐 | 49.37 次/秒 |

原始数据见 [HTTP 压测证据](evidence/load-evidence.txt)，热点执行计划见 [偏斜分布计划](evidence/skew-plan.txt)。429、5xx 和网络异常单独计错，不进入成功请求延迟样本。

这是一组固定负载、本机网络和特定数据分布的结果。每个客户端有节奏上限，因此这不是系统最大吞吐量，也不能推导公网、机械磁盘、多实例或另一台服务器的性能。

- 从访客编辑草稿开始，注册、登录后草稿保留并成功发布。
- 连续创建两层回复，展开父子分支，真实展示三层留言。
- 删除弹窗取消后内容保留；确认删除中间节点后显示占位，孙回复仍可见。
- 切换排序不清空草稿。
- 模拟离线，发布失败后草稿保留；恢复网络可继续操作。

## 启动、停止、重启

本机默认 JDK 17 不满足项目要求，因此项目 `.tools` 下使用独立 Java 21。没有改动系统默认 JDK，也没有安装全局 PostgreSQL 服务。

已执行两个启动脚本；后端首次完成 Flyway V1 迁移，后续启动确认版本一致、不重复建表。停止脚本经验证会关闭 API、连接池和 PostgreSQL；重启后留言 ID、正文和回复关系保留。

还单独启动生产 JAR，使用随机空闲 HTTP 端口连接本地 PostgreSQL，成功读取 `/api/health` 和已有留言列表，然后停止该验证进程。生产 JAR 的 classpath 不需要 embedded-postgres。

Windows 文件占用问题已处理：普通测试不重复 `npm ci`，需要干净安装时应先停止 Vite 并使用 `-CleanInstall`。已另行停止 Vite 后执行过 `npm ci`、构建和前端测试。

## 边界与后续工作

- Docker Compose 文件提供了外部 PostgreSQL 方案，本机没有 Docker，未运行此路径；默认本地方案已验证。
- 尚未部署到公网；HTTPS、反向代理、真实生产数据库权限和备份恢复需要在部署环境验收。
- 30 分钟空闲期限通过服务器配置实现；没有以真实时钟等待完整 30 分钟做浏览器验收。绝对过期已通过服务端测试，失效会话交互已通过浏览器模拟。
- 不保证无限资源；已证明 10,001 层的数据与迭代处理，超深交互依靠聚焦分支而不是一次挂载整棵树。
- 分支历史、缓存和导航均有上限；被回收的分支需要按需重新加载，历史上一页最多保留 50 个游标，聚焦回退最多保留 100 次。
- P1/P2 的管理员、举报审核、密码找回、通知、搜索、点赞与实时推送尚未实现。图片附件目前只支持单机本地文件目录，尚未接入对象存储、CDN、病毒扫描或图片编辑。
- 未进行断电故障注入、分布式部署、跨浏览器全矩阵、长达数小时的稳定性或渗透测试。

本报告按实际证据列出覆盖范围；需求中的 32 条验收场景仍可用于后续扩展组合和人工回归，不将单元测试数量等同于需求场景数量。
